# AI POD Builder Skills

Reusable print-on-demand instructions. Submit one new skill in a [pull request](CONTRIBUTING.md). Review rules live in [REVIEW_RULES.md](REVIEW_RULES.md).

## Maintainer setup

1. Create a public GitHub repository at `wawonaworldwide/skills` and put this directory's contents on `main`. If you choose a different repository path, update the site submission links.
2. Give the site maintainer sole write and merge access. Require pull requests and the status context **AI POD Builder / skill review** on `main`, with GitHub Actions as the expected source if available. Require branches to be up to date, disable bypass (including admins), and leave force pushes, deletion, auto-merge and merge queue off. When available, also restrict branch updates to the maintainer. If GitHub needs to see the context first, exercise the workflow using a fork before opening submissions. Keep the branch protection in force when importing first-party or external entries.
3. Add the repository Actions secret `OPENAI_API_KEY` and repository variable `SKILL_REVIEW_MODEL` for a Responses API model that supports Structured Outputs. Keep the key in Actions secrets. The review Action sends validated public submission text to the provider and uses a bounded response. The review does not approve or merge PRs.
4. Verify the status lands on the fork head SHA and blocks merging on a failing run. Verify a second push updates the one bot comment and resets review for the new SHA. Keep write access exclusive so collaborators cannot create competing statuses. Review the instructions yourself even on a PASS.
5. After a merge, the main workflow regenerates `skills-catalog.json` as a workflow artifact. Download the latest successful artifact from the protected main branch. In the site checkout, set `SKILL_CATALOG_PATH` to the absolute path of that JSON and run the normal Astro build. Once the site changes are approved and pushed, set the optional repository variable `SKILL_SITE_REF` to the full approved site commit SHA. The workflow then also rebuilds Astro on each merge and saves the static site as a separate artifact for review. The workflow has no deployment step.

Community submissions include the full package and default to the Community badge. The maintainer can curate AI POD Builder packages and verified Open source links using the same catalog format. External entries have the same three required files. Their SKILL.md consists of the heading `# Upstream skill`, a blank line and the same URL as `source_url`. Use the verified upstream MIT license. The site links to the original author’s instructions and downloads. Set the optional Actions variable `SKILLS_MAINTAINER` to the maintainer’s GitHub handle to enable those source types for PRs opened by that handle. For a link-only entry, independently verify the upstream license and instructions before merging.

The catalog uses the first-parent commit date on protected main as the review date. It assumes main only accepts maintainer-reviewed changes. The scanner catches common credential and private URL patterns. The maintainer should check for secrets, private destinations, license rights, and deceptive instructions before merging.
